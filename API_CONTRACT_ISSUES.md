# Проблемы с OpenAPI контрактом в api-contract.yaml

## Описание проблемы

В файле `docs/api-contract.yaml` маршруты описаны с префиксом `/api/files`, но в действительности в `server.js` маршруты файлов подключаются без этого префикса:

```javascript
app.use(filesRoutes(dbService, embeddings));  // Подключение без префикса
```

Поэтому, например, маршрут `/api/files/vectorize-ai-items`, описанный в контракте, на самом деле доступен как просто `/vectorize-ai-items`.

## Подтвержденные несоответствия

### 1. Маршрут `/vectorize-ai-items`
- **В контракте:** `/api/files/vectorize-ai-items`
- **В реальности:** `/vectorize-ai-items`
- **Описание:** Векторизация ai_item по списку id или full_name
- **Подтверждено тестами:** Да, маршрут работает как `/vectorize-ai-items`

### 2. Другие маршруты файлов
Аналогично, все маршруты из `routes/files.js` имеют ту же проблему:
- `/api/files/register-file` (в контракте) → `/register-file` (в реальности)
- `/api/files/file-chunks/{filename}` (в контракте) → `/file-chunks/{filename}` (в реальности)
- и т.д.

## Влияние

1. **Клиенты API получают ошибки 404**, когда следуют документации в `api-contract.yaml`
2. **Разработчики тратят время** на выяснение реальных путей
3. **Контракт не соответствует реализации**, что нарушает принципы проектирования API

## Возможные решения

### Вариант 1: Изменить подключение маршрутов (рекомендуется)
Изменить `server.js`:
```javascript
// Вместо
app.use(filesRoutes(dbService, embeddings));

// Использовать
app.use('/api/files', filesRoutes(dbService, embeddings));
```

### Вариант 2: Обновить контракт
Обновить `docs/api-contract.yaml`, убрав префикс `/api/files` из всех маршрутов файлов.

### Вариант 3: Комбинированный подход
Обновить контракт и подключение маршрутов для согласованности.

## Рекомендации

1. **Приоритет:** Высокий, так как это мешает интеграции
2. **Решение:** Вариант 1 (изменение подключения маршрутов в server.js)
3. **Обоснование:** Сохраняет семантически логичную группировку `/api/files/` для файловых операций

## Вывод

Контракт `api-contract.yaml` содержит ошибки, не соответствующие реальной реализации API. Эти ошибки необходимо исправить для обеспечения согласованности между документацией и реализацией.
